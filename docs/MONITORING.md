# Recurring investigative updates

Activated after the successful 2026-11-01 Pages launch. Task: `preparedness-weekly-investigation`. Schedule: Mondays at 9:00 a.m. America/New_York, starting November 2, 2026. The Codex app schedule is the source of truth for current enablement. No separate paid model API job is configured in GitHub Actions.

## Run contract

1. Work only in `<project-root>`. Read AGENTS.md, methodology, corrections, master assessment, research plan, website and archive documentation. Apply model routing. Check for concurrent changes before edits; never overwrite unrelated work.
2. Snapshot the local research before substantive changes. Verify the archive. Focus on priority-claim source integrity, then baseline completion and new public-source developments across all eight sectors.
3. Search for new and interesting evidence that supports, expands, refines **or contradicts** the core ideas. Prefer primary documents and independent reporting; identify repeated upstream origins. Do not invent operational deviations or treat preparedness as proof of imminent catastrophe.
4. Register sources, capture original bytes when available, record actual capture times, preserve failed retrievals, separate confirmed facts/reported claims/inferences/speculation, and update stable records. Do not confuse contract ceilings, obligations and deliveries. Retain 2023–2025 comparisons and unknown values.
5. Review changes against the publication contract. New public finding pages require verified confirmed documentary claims, traceable inspected sources, clear claim boundaries and no unsubstantiated consequential allegations. Review the prose itself; schema validation is insufficient. Keep ambiguous claims in the investigation queue; do not publish a broader threat conclusion without the necessary corroboration and comparison.
6. For qualifying changes, update findings, citations, corrections, assessment/cutoff and share images as appropriate. Run all checks and preview changed pages. Archive a post-update snapshot and portable backup. Commit only task-owned changes and push to main so Pages builds the site; inspect deployment success. If credentials or validation fail, preserve local work and report the blocking issue. Existing user-authorized API credentials may be used when helpful. Keep secrets outside public files and logs; do not create new subscriptions or invoke optional model adjudication without explicit opt-in. Do not implement the family planner.
7. Avoid cosmetic/no-evidence commits. Deduplicate unchanged material. Stay quiet if nothing meaningful changes; notify on material findings, corrections, deployment failures or required user action. Report what changed and its evidentiary limits, not a generic alarming headline.

## Operating limits

This is a local Codex task, not a continuously running public warning service. It depends on the machine/app and source access being available. A weekly review is not adequate for live hazard alerts, and the site must never present itself as one. Actual hazard warnings should be obtained from the relevant official service. Future cadence changes can be made in the Codex schedule.

Local scheduled tasks require the computer to be on and the app running with the project available. See [official OpenAI documentation](https://learn.chatgpt.com/docs/automations?surface=app).

Public presentation: follow the journalistic site standards in WEBSITE.md. Recheck changed public references, inspect supporting content, use credited source imagery, and keep roadmap/product planning local-only. Do not list unsourced leads as public investigations.
